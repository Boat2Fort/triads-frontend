# Gameplay audit — 17 October 2026

The reported Daily puzzle (BUTTON, PIGEON, PORT) was reproduced in Edge: BUTTON was accepted, CAMPAIGN and PANIC disappeared, and PUSH- remained. This audit followed cue identity through loading, matching, hints, answer feedback, round transitions, scoring, persistence, reloads, and Daily rollover.

## Validation

Final results: **214 frontend tests passed in Microsoft Edge** and **94 backend tests passed across 13 Jest suites**. Both production builds passed; changed TypeScript files passed lint and both repositories passed `git diff --check`. The frontend production build reports bundle-size (2.42 MB against the 2 MB warning threshold), CommonJS dependency, and CSS selector warnings; these are not compilation failures. Existing smoke-test setup was repaired where it omitted required inputs, providers, or current form data. Shared mutable form state was isolated between tests, and the stats smoke test waits for chart readiness before teardown.

Database concurrency tests simulate the relevant query interleavings through Prisma mocks. They do not constitute a production database load test. No deployment or production data migration was performed. The original live-site reproduction is in `../push-cue-glitch.png` relative to the frontend repository.

The separate existing change to `brain-warming-play-button.ts` is outside this audit.

## Deployment

Deploy the backend before the frontend. The backend accepts optional `triadGroupId`, `triadsStep`, and completion `puzzleDate` fields and continues to accept older clients. The current deployed backend rejects unknown request fields, so deploying the new frontend first would make gameplay requests fail validation. No schema migration is required.

After deployment, replay the BUTTON/PIGEON/PORT Daily: verify all three BUTTON bubbles disappear, the other initial triads clear, and the bonus round can be completed. Also check a saved Daily from before hyphen preservation and a failed bonus request followed by Retry bonus round.
